# Use remote expansion and reranking

QMDX will preserve QMD's local indexing, query embedding, BM25/vector retrieval, and reciprocal-rank fusion, but it will use remote inference for query expansion and reranking. QMDX integrates through QMD's public SDK, requests one fused candidate pool with local reranking disabled, and owns the final ordering and result contract without accessing QMD's SQLite schema directly. On the target workstation, QMD 2.8.3 could not allocate the required GPU contexts, while CPU reranking of 40 candidates took about 1 hour 45 minutes for one query; implementing local generation or reranking would therefore optimize for hardware other than the workstation where QMDX must deliver interactive search.

The stages remain independently observable so the full pipeline can be measured after implementation against the same-index, same-depth QMD local-retrieval baseline. Moving all retrieval online, reimplementing QMD's retrieval or fusion, requiring different local hardware, and retaining the multi-day local benchmark were rejected because they either abandon QMD's useful local index, duplicate its semantics, or fail the deployment constraint.
